# M0 全景与方法 · 设计稿

> 模块目标：给零基础读者一张**全领域地图**和一套**读论文的方法与指标语言**，让后面 66 课都有挂靠点。本模块不深入任何机制，宁浅勿漏。

## L01 全景图

- **文件**：`M0 全景与方法/L01 全景图.md`
- **定位**：全课程的「卫星地图」。以「用户发一句 prompt → 屏幕逐字吐出回答」和「一个模型从数据到权重」两条故事线，把课程 10 个模块串成一次完整旅程。读者读完不需要懂任何机制，但要知道**每个环节叫什么名字、在哪个模块深入**。
- **前置**：无
- **核心问题**：① ChatGPT 回答你的问题时，物理世界里到底发生了什么？② 训练一个大模型为什么需要上万张 GPU 和一整个数据中心？③ 这个领域的「系统问题」到底是哪几类？
- **内容要点**：
  1. 两条故事线开场：**推理线**（prompt → tokenize → prefill → 逐 token decode → 流式返回）与**训练线**（万亿 token 数据 → 数月万卡训练 → 一个权重文件）。此处每个词只给一句话定义 + 指向后续课程的链接。
  2. 分层地图（本课核心图）：模型层（Transformer/MoE）→ 框架层（PyTorch/Megatron/vLLM）→ 算子与通信层（CUDA kernel/NCCL）→ 单机硬件层（GPU/HBM/NVLink）→ 集群层（网络拓扑/存储/调度）→ 数据中心层（供电/散热/多集群）。每层给 2–3 个代表名词。
  3. **training vs inference** 两种 workload 的本质差异：一次性 vs 持续在线、吞吐导向 vs 时延导向、故障重来 vs 服务降级——引出课程组研究的三关键词：性能、资源效率、生存性。
  4. **scale-up vs scale-out**：机箱内加卡 vs 跨机加节点，一句话讲清为什么会有两套互联体系（NVLink vs 网络），细节留给 L25/L31。
  5. 数量级速览表（不推导，只建立体感）：GPT 级模型参数量 ~10¹¹–10¹²、训练数据 ~10¹³ token、训练计算量 ~10²⁵ FLOPs、一台 H100 节点算力 ~8×10¹⁵ FLOPS、万卡集群功率 ~10 MW。
  6. 课程导览：10 个模块分别回答什么问题（每模块一句话），三条速通路线怎么选。
- **必收术语**：training、inference、pretraining、serving、workload、GPU cluster、accelerator、scale-up、scale-out、AI Infra、MLSys、throughput-oriented、latency-oriented、token、model weights/checkpoint、frontier model。
- **定量环节**：数量级速览表本身（引用 [[03 约定与符号]]），并算一个「感受题」：15T token × 6N FLOPs/token 的 405B 模型 ≈ 3.8×10²⁵ FLOPs；若单卡有效 400 TFLOPS，一张卡要算 ~3000 年 → 所以需要上万张卡并行 → 所以并行与通信是本课程的主线。
- **图示**：① 分层地图（Mermaid，节点链接到各模块）；② 推理请求时序图（prompt→prefill→decode 流式）。
- **延伸阅读**：《Attention Is All You Need》（NeurIPS 2017，只看图 1 感受结构）；NVIDIA 官网 DGX/HGX 产品页（感受一台 AI 服务器长什么样）；任选一篇课程组在读论文的 Abstract（体会「读不懂」，学完再回来）。
- **误区**：「大模型 = 算法问题」——实际上 frontier 模型的成本与工程难度大头在系统；「推理很便宜」——全球推理总算力开销已远超训练。

## L02 如何读系统论文

- **文件**：`M0 全景与方法/L02 如何读系统论文.md`
- **定位**：方法课 + 指标语言课。前半教「系统论文的解剖结构与阅读顺序」，后半教「全领域通用的性能指标词汇」——这是唯一一处集中讲评测语言的地方，后面所有课都依赖。
- **前置**：[[L01 全景图]]
- **核心问题**：① 一篇 12 页的 NSDI 论文，研究生该按什么顺序读、读几遍？② Evaluation 里的图到底在证明什么？③ speedup、p99、strong scaling 这些词是什么意思？
- **内容要点**：
  1. 会议版图：系统类（OSDI/SOSP/NSDI/EuroSys/ATC/SoCC）、网络类（SIGCOMM/NSDI/INFOCOM/CoNEXT）、MLSys 类（MLSys）、体系结构类（ISCA/ASPLOS/HPCA）、HPC 类（SC/PPoPP/HPDC）；arXiv 文化（AI Infra 论文常先挂 arXiv）；期刊（ToN/TPDS/JSAC）在本领域的角色。每个会议一句话「它喜欢什么样的论文」。
  2. 系统论文八股解剖：Abstract（做了什么+数字结论）→ Intro（问题-现状-缺口-贡献四段论）→ Background/Motivation（往往是最好的教材！）→ Design → Implementation → Evaluation → Related Work。强调：**初学者读 Background 和 Motivation 的收益最大**。
  3. 三遍读法：第一遍 5 分钟（Abstract+Intro+全部图表标题）；第二遍 40 分钟（Design 主线+Evaluation 主图）；第三遍按需（复现/审稿级）。给一张「读完应能回答的 6 个问题」清单（研究对象、workload、瓶颈、优化变量、目标函数、baseline）。
  4. 指标语言（本课硬核部分）：**latency vs throughput** 与两者的 tradeoff 曲线；**percentile**（p50/p95/p99、tail latency，为什么平均值会骗人）；**CDF 图怎么读**；**speedup 与 baseline 选择**；**strong scaling vs weak scaling**；**Amdahl's Law**（推导 + 例：95% 可并行部分的上限是 20×）；**goodput vs throughput**；归一化与「x 轴对数」陷阱。
  5. 实操建议：术语积累习惯（遇到不认识的词 → 查 [[02 术语总表]] → 没有就记下来）；用 AI 辅助读论文的正确姿势（让 AI 解释术语可以，让 AI 替你判断贡献不行）。
- **必收术语**：venue、camera-ready、artifact、baseline、ablation study、workload、trace、testbed、end-to-end、latency、throughput、goodput、tail latency、percentile（p50/p99）、CDF、speedup、scalability、strong scaling、weak scaling、Amdahl's Law、overhead、SLO（预告，L55 深入）、state-of-the-art（SOTA）。
- **定量环节**：Amdahl's Law：可并行比例 f=95%，无限卡加速上限 1/(1−f)=20×；再算 f=99%、1024 卡的实际加速 ≈ 91×，说明「为什么万卡训练里 1% 的串行/等待都致命」。
- **图示**：① 论文结构-阅读顺序图；② 手绘风格的示例 CDF 图 + 标注 p50/p99；③ strong vs weak scaling 曲线对比。
- **延伸阅读**：S. Keshav《How to Read a Paper》（经典三遍读法出处）；任选一篇 MegaScale（NSDI 2024）或 vLLM（SOSP 2023）的 Intro 做「六个问题」练习。
- **误区**：「p99 高一点没关系」——一次请求扇出 100 个子请求时，p99 几乎必然命中；「加速比高 = 系统好」——要看 baseline 是否够强、是否 apples-to-apples。
