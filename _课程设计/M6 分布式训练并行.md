# M6 分布式训练并行 · 设计稿

> 模块目标：课程的心脏。学完读者能对论文里任何一句「we train with TP=8, PP=16, DP=128, ZeRO-1, selective recomputation」**完整解码**：每个维度切了什么、通信原语是什么、消息多大、发生在哪条链路上、显存省在哪。每课固定输出「三账」：显存账、通信账、适用条件。统一用 03 的参考模型（Llama-3-8B/70B/405B）做例子。

## L40 训练显存全解剖

- **文件**：`M6 分布式训练并行/L40 训练显存全解剖.md`
- **定位**：整个模块的「总动机」课：把一张 GPU 训练时的显存逐字节数清楚，得出「为什么 70B 单卡训不了」的精确答案。**16 B/参数记账法**与 **activation 公式**在此立起，后面每课都引用。
- **前置**：[[L06 优化器]]、[[L05 反向传播与梯度]]、[[L13 自回归生成与KV缓存]]
- **核心问题**：① 训练一个 8B 模型到底要多少显存、都花在哪？② activation 占用怎么估、为什么随 batch 和序列长度线性爆炸？③ 「显存不够」有哪几族解法（本模块地图）？
- **内容要点**：
  1. 四大件清单（混合精度口径，引 03）：**params**（BF16, 2N）+ **gradients**（BF16, 2N）+ **optimizer states**（FP32 master + m + v，12N）= **静态 16N 字节**；与推理只需 2N 的对比（8×差距）。
  2. **activation memory**：为什么存在（回收 L05 的 backward 依赖）；量级公式：与 L、S、b、d 成正比 + attention 的 S² 项；给 Megatron 论文的每层估算式（≈ sbh(34 + 5as/h) 字节/层，**须核实**《Reducing Activation Recomputation in Large Transformer Models》式(2) 后引用，a=头数）；「静态是常数、activation 是变量」的管理学差异。
  3. 完整算例（本课高光）：Llama-3-8B、S=8192、b=1：静态 128 GB（已爆 80 GB！）+ activation 每层 ~2 GB 级 → 结论：**8B 模型单卡都训不动**（不开任何优化时）；70B 静态 1.12 TB → 至少 14 张卡只为放状态。
  4. 其他占用零头：CUDA context、NCCL buffer、框架 workspace、fragmentation（回收 L21 reserved vs allocated）——「论文表格对不上你实测」的常见原因。
  5. 解法地图（本模块+M7 的目录页）：**切碎状态**（ZeRO/FSDP→L42）、**切碎模型**（TP→L43、PP→L44）、**切碎序列**（CP→L45）、**切碎专家**（EP→L46）、**不存重算**（recomputation→L50）、**挪走**（offload→L50）、**换格式**（低精度→L49）。每条一句话+链接，让读者拿到全局菜单。
- **必收术语**：memory footprint、static/model states vs activation memory、parameters/gradients/optimizer states（回收）、master weights、activation checkpointing（预告）、per-parameter bytes（16B 记账）、residency、fragmentation（回收）、memory wall。
- **定量环节**：上面算例全程 + 反向练习：「一张 80 GB 卡、不开优化，最大能全参训练多大的模型？」（≈ 80/16 ≈ 5B 减 activation 余量 → 3–4B）——这道题的答案是整个 M6 存在的理由。
- **图示**：① 显存构成堆叠柱状图（8B 训练 vs 推理对比，本模块封面图）；② 解法地图（思维导图式，节点链接各课）。
- **延伸阅读**：ZeRO 论文《ZeRO: Memory Optimizations Toward Training Trillion Parameter Models》（SC 2020）第 3 节（显存分析的正典）；《Reducing Activation Recomputation in Large Transformer Models》（Korthikanti et al. 2022，activation 公式出处）。
- **误区**：「显存 = 参数大小」——训练时是 8 倍以上；「OOM 加卡就行」——不改并行策略，加卡不减单卡占用（DP 不省显存！下课展开）；把推理显存经验带入训练。

## L41 数据并行与DDP

- **文件**：`M6 分布式训练并行/L41 数据并行与DDP.md`
- **定位**：第一种也是最普遍的并行。讲透 DDP 的梯度 all-reduce 时序（bucketing+overlap），并给出「DP 不省显存」与「DP 通信量与卡数无关」两个反直觉结论。附参数服务器历史。
- **前置**：[[L40 训练显存全解剖]]、[[L36 集合通信原语]]、[[L37 通信算法与代价模型]]
- **核心问题**：① DP 在数学上为什么等价于大 batch 单卡训练？② 梯度同步的通信量、时机、与计算的重叠怎么做？③ 为什么 DP 是「显存的敌人、吞吐的朋友」？
- **内容要点**：
  1. 机制：每卡完整模型副本 + 数据切片；forward/backward 独立 → **梯度 all-reduce（求平均）** → 各自更新（结果一致，等价于 GBS=Σb 的单卡训练）；「同步 SGD」语义。
  2. **DDP 工程**：**gradient bucketing**（攒桶发送，摊薄 α）+ **通信-计算重叠**（backward 逐层出梯度、后层桶先飞——为什么桶按反向顺序排）；重叠时序图（本课主图）；no_sync/梯度累积交互一句话。
  3. 三账：显存——**一点不省**（每卡全量 16N）；通信——每 step 每卡 ≈ 2×2N 字节（BF16 梯度 all-reduce），**与 DP 度无关**（回收 L37 ring 性质）；适用——模型单卡装得下时的默认选择。
  4. **scaling 语义**：加卡 = 加 GBS（weak scaling）；large-batch 训练的收益递减与 LR 调整（linear scaling rule 一句话 + LAMB 提名）——「DP 度不是想加就加」的算法约束（预埋 L47 的 batch 预算观念）。
  5. 历史纵深：**parameter server**（异步/有界异步、staleness——2014 时代的选择，为何被同步 all-reduce 取代：收敛性+带宽对称性）；但 PS 思想在**联邦/跨域**场景复活（预告 L63）——「架构没有死，只有换战场」。
  6. 效率现实：通信/计算比公式（2×2N/带宽 vs 6N·b·S/算力）→ 什么时候通信开始吃掉扩展性（小模型大集群最惨）→ 重叠能藏多少。
- **必收术语**：data parallelism、replica、synchronous SGD、gradient synchronization、DDP、gradient bucketing、communication-computation overlap、no_sync、linear scaling rule、LAMB（提名）、parameter server、worker/server、asynchronous SGD、staleness、BSP/ASP（bulk-synchronous 一句话）。
- **定量环节**：8B 模型、DP=64、H100+400G：每 step all-reduce 16 GB×2(p−1)/p ≈ 32 GB → /50 GB/s ≈ 0.64 s；每 step 计算（b=2, S=8192, 每卡 GBS 份额）≈ 6×8e9×16384 FLOPs/989T·40% ≈ 2.0 s → 通信占比 ~24%，重叠后可藏大半——「能不能 scale 先算这个比值」。
- **图示**：① DP 结构图（副本+数据分片+all-reduce）；② backward 与桶通信的重叠时序图（本课主图）；③ PS vs all-reduce 架构对比图。
- **延伸阅读**：PyTorch DDP 论文《PyTorch Distributed: Experiences on Accelerating Data Parallel Training》（VLDB 2020，bucketing/overlap 细节）；《Scaling Distributed Machine Learning with the Parameter Server》（OSDI 2014，历史正典）。
- **误区**：「DP 能解决 OOM」——不能，它复制模型；「加倍卡数=加倍速度」——batch 语义变了，还有通信税；「PS 过时了」——跨域/联邦场景它是主流架构。

## L42 ZeRO与FSDP

- **文件**：`M6 分布式训练并行/L42 ZeRO与FSDP.md`
- **定位**：把 DP 的冗余状态切碎——理解 ZeRO 三阶段各切什么、通信怎么从 all-reduce 变成 RS+AG，以及 PyTorch FSDP 的对应关系。M6 的技术转折点。
- **前置**：[[L41 数据并行与DDP]]、[[L36 集合通信原语]]（RS+AG 分解）
- **核心问题**：① ZeRO-1/2/3 分别切掉什么、显存各降到多少？② 为什么切了状态之后通信原语必须换？③ FSDP 与 ZeRO-3 什么关系、HSDP 又是什么？
- **内容要点**：
  1. 观察起点：DP 的浪费——p 份一模一样的 optimizer states/gradients/params；ZeRO 的宣言：**冗余的都切掉，用通信换显存**。
  2. 三阶段逐个拆（每阶段：切什么/每卡显存公式/通信流程图）：**ZeRO-1**（切 optimizer states：4N+12N/p）——梯度 all-reduce 改为 RS（各拿自己那片）+更新+参数 AG；**ZeRO-2**（再切梯度：2N+14N/p）；**ZeRO-3**（全切：16N/p）——参数也分片，**用时才 all-gather、用完即丢**（forward/backward 各一轮 AG）。
  3. 通信账对比表：ZeRO-1/2 ≈ DP 同量（2n 换成 RS n + AG n）；**ZeRO-3 ≈ 1.5×DP**（多一轮前向 AG）——「显存降 p 倍、通信只多 50%」为什么划算；但消息碎、α 敏感、prefetch 关键（一句话）。
  4. **FSDP**：PyTorch 官方 ZeRO-3（flat parameter、wrapping unit、prefetch）；**HSDP**（hybrid：节点内 full-shard + 节点间 replicate——把 AG/RS 关进 NVLink 域、跨网只走梯度 all-reduce，拓扑感知思想的教科书案例，回收 L37 分层）；FSDP2/DTensor 一句话提名。
  5. 延伸家族：**ZeRO-Offload/Infinity**（状态挪去 CPU/NVMe，预告 L50）；MiCS/ZeRO++ 一句话提名（分片域缩小/量化通信）。
  6. 选型判据（vs TP 的第一次交锋，L47 完整版）：ZeRO-3 是「DP 的显存改良」，不切算子——单层放不下（超大 d）或需要更小 TTFT 时仍需 TP；通信粒度（ZeRO 按参数块、TP 按 activation）导致的重叠难易差异一句话。
- **必收术语**：ZeRO、stage 1/2/3、partitioning/sharding、redundancy、FSDP、flat parameter、wrapping、prefetch、HSDP/hybrid sharding、DTensor（提名）、ZeRO-Offload/Infinity（预告）、ZeRO++（提名）、all-gather on demand、communication volume overhead。
- **定量环节**：70B 模型（静态 1.12 TB）：DP 每卡 1.12 TB（不可行）→ ZeRO-1（p=64）：140+175/64 ≈ 143 GB？——期望实现者按公式 4N+12N/p 与 2N+14N/p、16N/p 分别算 p=64/512 两档，做成表格；结论：ZeRO-3 + p=512 → ~2.2 GB/卡（+activation 才是大头）——「状态问题解决了，activation 问题登场」（引向 L43/L50）。
- **图示**：① 三阶段显存瀑布图（16N→4N+…→16N/p）；② ZeRO-3 的 AG-用-丢时序图（本课主图）；③ HSDP 两级结构图。
- **延伸阅读**：ZeRO 论文（SC 2020，图 1 是三阶段正典图）；PyTorch FSDP 论文/官方教程；HuggingFace《Ultra-Scale Playbook》ZeRO 章（免费在线书，本模块最佳伴读，此处首次推荐）。
- **误区**：「ZeRO 是模型并行」——它是 DP 的显存优化，计算仍是数据并行语义；「ZeRO-3 通信爆炸」——只有 1.5×，真正的代价是碎消息与调度复杂度；「FSDP 和 ZeRO 是竞品」——同一思想两个实现。

## L43 张量并行

- **文件**：`M6 分布式训练并行/L43 张量并行.md`
- **定位**：切开算子本身：Megatron 列切/行切的矩阵推导（本课有真正的数学，务必图解到位）、每层两次 all-reduce 的由来、以及「TP≤8/不出机箱」的定量论证。
- **前置**：[[L12 Transformer全解剖]]、[[L36 集合通信原语]]、[[L25 节点内互联]]
- **核心问题**：① 一个矩阵乘怎么切给多卡而结果不变？② 为什么 FFN 要「先列后行」、attention 按头切？③ 为什么 TP 的通信必须走 NVLink？
- **内容要点**：
  1. 动机：ZeRO 切的是「放置」，TP 切「计算」——单层太大/单卡算不动/要压低单步时延时的选择。
  2. **列切与行切**（本课数学高光，2×2 分块矩阵图解）：Y=XW 列切 W=[W₁,W₂] → 各卡得 Y 的列片，**无需通信**但输入 X 要全量；行切 W 竖劈 + X 对应列片 → 各卡得部分和，**需 all-reduce**。
  3. **Megatron 组合拳**：FFN = 列切(W_up) → GeLU → 行切(W_down) → 一次 all-reduce；attention = 按头切 QKV（天然列切）→ 行切 W_O → 一次 all-reduce；**每层 forward 2 次 all-reduce、backward 2 次**——数字要钉死（读者以后靠它算通信量）。
  4. 通信账：每次 all-reduce 消息 = activation 尺寸 b×S×d×2B（不是参数！与 DP 的本质区别）；每 token 每层固定 8×d 字节级——推出「通信频繁且在关键路径上（无法像 DP 那样藏进 backward）」→ 必须 <µs 级时延+TB 级带宽 → **只能 NVLink 域内**（用 03 数字对比 NVLink vs 400G 下的每层通信耗时，差 9×——L25 伏笔在此收割）。
  5. **Megatron 式 sequence parallelism**：LN/dropout 区域按序列切，把 all-reduce 换成 AG+RS（等量但可与计算流水）——省 activation 显存的关键补丁（与 L45 的 context parallelism 命名辨析，此处必须立牌坊：**Megatron-SP ≠ CP**，论文里这两个词经常打架）。
  6. 工程杂项一句话each：vocab/embedding 并行、TP 与 GQA 的头数整除约束、async-TP/通信重叠研究（提名）。
- **必收术语**：tensor parallelism（TP）、model parallelism（历史词辨析）、column/row parallel linear、partial sum、identity vs all-reduce（f/g 算子）、attention head sharding、Megatron-LM、sequence parallelism（Megatron-SP）、activation 通信、TP degree、intra-node parallelism。
- **定量环节**：Llama-3-70B、TP=8、S=8192、b=1：每层 all-reduce 消息 = 8192×8192×2B = 128 MB，80 层×前后向 4 次 = 320 次/step；NVLink（450 GB/s 有效～300）下每次 ~0.4 ms vs 400G 网卡（50 GB/s）~2.6 ms → TP 走网络时每 step 多付 ~0.7 s 纯通信——「TP 不出机箱」不是教条是算术。
- **图示**：① 列切/行切分块矩阵图（本课主图，必须极清晰）；② Transformer 层的 TP 数据流全图（标 f/g 通信点）；③ NVLink vs 网络的每层通信耗时柱状图。
- **延伸阅读**：《Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism》（2019，图 3/图 4 是正典）；《Reducing Activation Recomputation…》（2022，Megatron-SP 出处）；Ultra-Scale Playbook TP 章。
- **误区**：TP=「把层分到不同卡」——那是 PP；TP 切的是**同一层内部**；「TP 度越高越好」——通信在关键路径，超过 NVLink 域断崖恶化；忘记 backward 也要通信（通信量 ×2）。

## L44 流水线并行

- **文件**：`M6 分布式训练并行/L44 流水线并行.md`
- **定位**：按层切模型 + 流水线调度学。气泡率公式、1F1B/interleaved/zero-bubble/DualPipe 谱系、以及「PP 通信最便宜」的网络视角结论。
- **前置**：[[L43 张量并行]]、[[L40 训练显存全解剖]]
- **核心问题**：① 朴素按层切为什么只有 1/p 利用率？② micro-batch 和 1F1B 怎么把气泡压下来？③ 为什么说 PP 是「对网络最友好」的并行？
- **内容要点**：
  1. 机制：模型按层切成 p 个 **stage**，卡间只传 stage 边界的 activation（**P2P send/recv**）；朴素调度 = 每卡干 1/p 时间 → **bubble** 概念登场。
  2. **GPipe**：把 batch 切成 m 个 **micro-batch** 流水填充；**气泡率推导**：(p−1)/(m+p−1)（本课核心公式，配甘特图推导）；m 要多大才把气泡压到 5%（m ≈ 19(p−1)）→ 与 GBS 预算的冲突（预埋 L47）。
  3. **1F1B（PipeDream 血统）**：交替一前一后 → 在飞 activation 从 m 份降到 p 份（**省显存**，气泡率不变）；warmup/steady/cooldown 三段甘特图。
  4. **interleaved（virtual stages，Megatron）**：每卡持多段非连续层 → 气泡 ÷v、通信 ×v 的 trade；**zero-bubble（ZB-H1/V）**：把 backward 拆成对输入/对权重两半来填洞（直觉级）；**DualPipe**（DeepSeek-V3）：双向流水 + 前反向阶段互相掩盖 A2A 通信——「调度即艺术」的当代样本（与 L46 呼应）。
  5. 三账：显存——参数/p + 在飞 activation p 份（首尾 stage 不均衡问题一句话：embedding/loss 层的摆放）；**通信——每 micro-batch 每边界只传 b_micro×S×d×2B 的 P2P，量小、点对点、可跨慢网**（与 TP 对照表：这就是「PP 跨机、TP 机内」的分工根源，也是跨域训练的伏笔 L63）；适用——超深模型、跨节点扩展。
  6. 负载均衡工程一句话：按层 FLOPs 均分 stage、首尾特殊层的补偿。
- **必收术语**：pipeline parallelism（PP）、stage、micro-batch、pipeline bubble、bubble ratio、GPipe、1F1B、warmup/steady/cooldown、PipeDream（认名）、interleaved pipeline/virtual stage、zero-bubble pipeline、DualPipe（认名）、P2P activation transfer、pipeline flush、stage balancing。
- **定量环节**：p=16、m=64：气泡率 15/(64+15) ≈ 19%；要压到 5% 需 m≈285 → 若 b_micro=1、S=8192，GBS 就被顶到 285×8192×DP ——「气泡、GBS、DP 度三者在抢同一个预算」（L47 的核心矛盾提前亮相）。通信账：每边界每 micro-batch 传 8192×8192×2B=128 MB（b=1, d=8192），在 400G 上 2.6 ms——与该 stage 计算时间对比得出「可流水掩盖」结论。
- **图示**：① 朴素 vs GPipe vs 1F1B 三联甘特图（本课主图，务必精确）；② interleaved 的 v=2 甘特图；③ 「并行方式×通信特征」对照表（TP vs PP vs DP，为 L47 铺桌）。
- **延伸阅读**：GPipe（NeurIPS 2019）与 PipeDream（SOSP 2019）——各读核心图；《Zero Bubble Pipeline Parallelism》（ICLR 2024，选读）；DeepSeek-V3 报告 DualPipe 节（配合 L46）。
- **误区**：「PP 的卡在轮流休息所以没用」——1F1B 稳态下人人满载，气泡只在首尾；「气泡是 bug」——是同步流水的数学必然，只能摊薄不能消灭（zero-bubble 是拆算子填洞）；把 PP 的 stage 间 P2P 误当集合通信。

- **核心问题**：① S=1M 的 activation 单卡装不下怎么办？② attention 需要全序列交互，序列切开后怎么算对？③ Megatron-SP、DeepSpeed-Ulysses、Ring Attention、CP 这些词什么关系？
- **内容要点**：
  1. 动机定量开场：S=1M、d=8192 的单层 activation ≈ 16 GB×若干——长上下文训练的显存像 S 线性爆炸、attention 计算像 S² 爆炸 → 必须切序列。
  2. 难点定位：FFN/LN 对序列是逐位置的（切了白切，无需通信）；**唯一麻烦是 attention**——每个 Q 要见所有 KV。
  3. **Ring Attention（P2P 流派）**：KV 分块绕环流动、每卡边收边算 online softmax 累积（与 FlashAttention 的亲缘一句话，L51）；通信可与计算重叠；**causal 负载不均**问题与 zigzag/负载均衡切法（后半段序列计算多——图解）。
  4. **DeepSpeed-Ulysses（A2A 流派）**：序列切 → attention 前 all-to-all 换成「头切」→ 算完换回；通信量分析与头数上限约束（并行度 ≤ h）。两流派对照表（通信原语/重叠性/约束/代表实现）。
  5. **命名大扫除**（本课的公共服务）：Megatron-SP（L43，切的是 LN/dropout，为省显存）vs **context parallelism**（本课，切 attention 的序列维）；「sequence parallelism」在不同论文里指哪个——给读者一张「看到这个词先查哪年哪家」的鉴别表。
  6. 现实应用：Llama-3 的长上下文阶段用 CP；推理侧 CP（超长 prompt 的 prefill 并行）一句话预告 L60；与 PP/TP 的组合位置（L47）。
- **必收术语**：context parallelism（CP）、sequence parallelism（辨析）、Ring Attention、online softmax（预告 L51）、zigzag/load-balanced sharding、DeepSpeed-Ulysses、all-to-all head switching、causal load imbalance、long-context training、activation 与 S 的线性/平方关系。
- **定量环节**：Ring Attention 通信账：CP=8、S=128K、d=8192：每卡每步绕环收发 KV 块总量 = 2×S×d×2B×(p−1)/p ≈ 3.7 GB？——期望实现者按块流动模型仔细算（KV 全量 ×2B×(p−1)/p），并与该卡 attention 计算 FLOPs（S²d/p 份额）对比，论证「长序列下计算 ≫ 通信 → 可完美重叠」；短序列时结论反转 → 「CP 是长文专用」。
- **图示**：① Ring Attention 环形流动图（本课主图）；② Ulysses 的两次 A2A 维度变换图；③ SP/CP 命名鉴别表。
- **延伸阅读**：《Ring Attention with Blockwise Transformers for Near-Infinite Context》（2023）；DeepSpeed-Ulysses 论文/博客；Llama-3 报告的 context parallelism 段。
- **误区**：把 CP 与 Megatron-SP 混为一谈（最常见的读论文事故之一，本课专治）；「切序列会算错 attention」——数学上 exact，靠 online softmax/A2A 保证；「CP 万能」——短序列下通信藏不住，纯赔。

## L46 专家并行与MoE训练

- **文件**：`M6 分布式训练并行/L46 专家并行与MoE训练.md`
- **定位**：MoE 的系统面：EP 放置、all-to-all 双程的解剖、负载不均→straggler、以及 DeepSeek-V3 的教科书级工程（node-limited routing/DualPipe/DeepEP）。网络研究者的富矿课。
- **前置**：[[L17 MoE混合专家]]、[[L36 集合通信原语]]、[[L44 流水线并行]]
- **核心问题**：① 专家散在各卡后，一个 token 的旅程是什么？② all-to-all 为什么难伺候（vs all-reduce）？③ 负载不均怎么变成全局 straggler、工程上怎么治？
- **内容要点**：
  1. **EP 机制**：E 个专家摊到 ep 组卡上；token 旅程六步图：router 打分 → **dispatch all-to-all**（token 按目的地重排发走）→ 专家 FFN → **combine all-to-all**（回家加权合并）——**每 MoE 层两次 A2A、backward 再两次**。
  2. A2A 的难缠之处（对照 all-reduce）：数据量**数据依赖**（路由结果决定，每步不同）→ 无法静态优化；天然多对多打满对分带宽（回收 L37）；易 incast（回收 L30）；消息大小 = tokens×k×d×2B 的推导。
  3. **负载不均的系统学**：热门专家所在卡成为 straggler → 同步语义下全员等（A2A 是 barrier 级）；治理三层：算法层（aux loss/aux-free，回收 L17）、容量层（capacity factor 截断 vs dropless 的 padding/波动）、**放置层**（**EPLB**——按历史负载重排专家副本，DeepSeek 开源件）。
  4. **DeepSeek-V3 案例研读**（本课高光，H800 约束下的工程课）：**node-limited routing**（每 token 限定 ≤M 个节点 → 跨机 A2A 流量受控 + NVLink 域内转发）；**DualPipe** 把 A2A 藏进流水线气泡（回收 L44）；**DeepEP** 通信库（NVLink+RDMA 两级、dispatch/combine 定制 kernel、低精度传输）；SM 占用与通信 kernel 的资源竞争一句话（回收 L38）。
  5. EP 与其他维度的关系：EP 常复用 DP 维（同一组卡既是 DP 又是 EP——「attention 部分是 DP、FFN 部分是 EP」的精确表述）；EP×TP 的组合约束一句话（L47 收口）。
- **必收术语**：expert parallelism（EP）、dispatch/combine、all-to-all（回收深化）、token routing、load imbalance、hot expert、capacity factor（回收）、token dropping/dropless（回收）、EPLB、expert placement、node-limited/group-limited routing、DualPipe（回收）、DeepEP（认名）、grouped GEMM（提名）、straggler（正式定义于此）。
- **定量环节**：DeepSeek-V3 风格 A2A 账：b×S=4096 token/卡、k=8、d=7168、BF16：dispatch 每卡发出 4096×8×7168×2B ≈ 0.47 GB/层/方向；61 层中 MoE 层 ×每 step 4 次 A2A → 每卡每 step 跨网 A2A 总量 ~百 GB 级 → 400G 网卡上裸传需秒级 → **不重叠 = 不可训**；node-limited 把跨机份额砍到 k_node/k——算出砍多少。（数字按公式走，标注「具体配置以报告为准」。）
- **图示**：① token 六步旅程图（本课主图）；② 负载不均热力图示意（专家×时间）；③ node-limited routing 的两级转发图。
- **延伸阅读**：DeepSeek-V3 技术报告 infrastructure 章（**本课程全书级重点文献**，此课精读其 MoE 工程部分）；DeepEP/EPLB GitHub README；《GShard》（2020，EP 的开山，选读）。
- **误区**：「MoE 省算力所以训练更快」——通信与不均可能把省的全吐回去，系统工程决定成败；「A2A 和 all-reduce 差不多」——一个数据依赖一个静态、优化空间完全不同；「负载均衡是算法问题」——放置与路由的系统手段同样关键（这正是网络研究者的切入点）。

## L47 混合并行组装

- **文件**：`M6 分布式训练并行/L47 混合并行组装.md`
- **定位**：模块收口课：把 DP/ZeRO/TP/PP/CP/EP 六个维度拼成一台真机的配置，讲清「维度×拓扑」的映射法则与 batch 预算的全局约束。读完这课，论文 setup 段落全文透明。
- **前置**：[[L41 数据并行与DDP]]～[[L46 专家并行与MoE训练]] 全部
- **核心问题**：① 六个维度怎么同时生效（device mesh 语义）？② 「TP 放机内、PP 跨机、DP 最外」的排序为什么几乎是定律？③ 给定卡数和模型，怎么系统地推出一组合法配置？
- **内容要点**：
  1. **device mesh**：总卡数 = DP×TP×PP（×CP，EP 复用 DP）——多维网格坐标系；一张 512 卡 = DP8×PP8×TP8 的三维图（本课主图）；每个 rank 同时属于多个 process group。
  2. **映射定律推导**（用 L41–L46 的通信账拼出）：通信频率×消息大小×可重叠性三指标排序：TP（每层多次、activation 级、难藏）→ 必须 NVLink；CP/EP（每层、可部分重叠）→ 尽量机内或近邻；PP（每 micro-batch、小 P2P）→ 可跨慢链路；DP/ZeRO（每 step 一次、大而可重叠）→ 最外层。给「通信密度决定物理距离」的一句话定律。
  3. **全局预算约束**：GBS = b_micro × GA × DP 且 m=GA 要够大压气泡（回收 L44）且 GBS 有算法上限（回收 L41）——三方拉扯的示意图；「为什么不能无脑加 DP」的完整答案。
  4. 显存-通信-气泡三账合流：给一张「维度增减对三账的影响方向」矩阵表（+TP → 显存↓通信↑↑；+PP → 显存↓气泡↑；+DP → 吞吐↑显存不变…）。
  5. **真实配置解码**（本课高光，逐字段翻译两个公开例子）：Llama-3-405B（16K 卡：TP8+PP16+DP128、后期 +CP，数字以报告为准）与 DeepSeek-V3（EP+PP+ZeRO-1 风格、无 TP——为什么？MLA+细粒度专家的显存结构 + H800 NVLink 被砍 → 印证「配置是约束的函数」）。
  6. 自动并行一段话：Alpa/自动搜索的思路与现实（搜索空间大、成本模型难准）——「所以 2026 年还是老师傅手工配」+ 这是研究机会（成本模型 = 课题组仿真方向的接口，L66）。
- **必收术语**：hybrid/3D/4D parallelism、device mesh、process group（回收）、parallel plan/strategy、mapping、GA（gradient accumulation，回收）、micro-batch budget、auto-parallelism、Alpa（认名）、GSPMD（提名）、cost model（预告 L66）、「TP intra-node」law。
- **定量环节**：完整推演一遍（这是 L48 实践的示范解）：70B 模型、512×H100（64 节点×8）、S=8192、目标 GBS=1024：候选 TP8-PP8-DP8 vs TP8-PP4-DP16 vs ZeRO3-DP512——每候选算：每卡静态显存、activation（选 recompute 档位）、每 step 通信量按链路分解、气泡率 → 选出可行解并说明 trade。表格呈现。
- **图示**：① 512 卡 device mesh 三维图（本课主图）；② 「通信密度→物理层级」映射图（六维度落位 NVLink/机内/跨机）；③ 三账影响方向矩阵。
- **延伸阅读**：《Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM》（SC 2021——3D 并行正典，setup 表精读）；Llama-3 报告 4.3 节；Ultra-Scale Playbook 的 5D parallelism 章（cheatsheet 级）。
- **误区**：「并行度越高越好」——每个维度都有边际代价，配置是求解不是堆料；「有了 ZeRO 就不需要 TP/PP」——activation 与单层规模它管不了；照抄别人配置——拓扑/带宽/模型结构一变，最优解就变（这正是「拓扑感知」研究存在的理由）。
