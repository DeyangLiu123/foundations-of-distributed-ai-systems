## L63 跨域与跨集群训练

- **文件**：`M9 前沿专题/L63 跨域与跨集群训练.md`
- **定位**：单集群到多集群/多地域的训练前沿：动机（电力/供给/主权）、WAN 约束下的通信算法谱系（分层同步→local SGD→DiLoCo→异步/去中心化）、与联邦学习的血缘。课题组「多集群/多地域」关键词的正课。
- **前置**：[[L47 混合并行组装]]、[[L44 流水线并行]]、[[L41 数据并行与DDP]]（PS 历史）、[[L30 无损网络与拥塞控制]]
- **核心问题**：① 为什么万卡之后「再大」的瓶颈不是钱是电？② 跨 DC 链路（带宽/时延/抖动/费用）比集群内差几个量级、哪些并行维度先死？③ 通信频率怎么一步步被算法「稀释」（从每 step 到每 H step）？
- **内容要点**：
  1. 动机三角：**电力墙**（单园区供电上限 → 吉瓦级需求必须多址，回收 L27）、GPU 供给与地缘（多云/多区采购）、数据主权/合规；「scale-out 的 scale-out」。
  2. 约束定量化（本课的物理基础）：集群内 400G×8/节点 vs 跨域专线（10–100 Gb/s 共享、RTT 10–100 ms、按流量计费、抖动与可用性）——带宽差 2–3 个量级、时延差 3–4 个量级；用 L37 α-β 模型重算 all-reduce：跨域同步 DP 每 step 分钟级 → 朴素方案死刑。
  3. 并行维度的「出域体检」（回收 L47 映射定律做跨域版）：TP 死、EP 死、DP 垂危、**PP 意外能活**（stage 间 P2P 小且可流水，回收 L44 伏笔）——多 DC 流水线切分的研究线（认名级引用近年 multi-DC training 工作，定性）。
  4. **通信稀释谱系**（本课主线，按「同步频率↓、算法风险↑」排布）：分层 all-reduce（域内密、域间疏，回收 L37）→ **local SGD/周期平均**（H 步一同步）→ **DiLoCo**（内环 AdamW + 外环 Nesterov 的双优化器结构、H~百步级；OpenDiLoCo/INTELLECT 的洲际实证认名）→ **异步/半异步**（PS 幽灵回归，回收 L41：staleness 重现）→ **去中心化/gossip**（认名级）。每档给：通信量公式、收敛性代价的定性描述、代表工作。
  5. **通信压缩工具箱**（正交手段，各一句话+认名）：梯度稀疏化（Top-K+error feedback）、量化通信（回收 L49 伏笔）、低秩（PowerSGD）——「压缩率 vs 收敛税」的评估语言。
  6. **联邦学习的血缘辨析**：FedAvg 本质 = local SGD + 非 IID 数据 + 端设备约束；「跨 DC 训练 ≈ 数据中心版联邦」的异同表（信任模型/数据分布/规模/瓶颈）——帮读者把 FL 文献批判性地据为己用（课题组边界：FL 算法本身不做，机制可借鉴）。
  7. 与研究的连接（写实）：多域间的拓扑/带宽感知任务切分、跨域故障域隔离（一个 DC 掉线怎么办——接 L53 生存性）、跨域流量工程与计费优化、仿真评估路径（接 L67）。
- **必收术语**：multi-datacenter training、cross-region、WAN、dedicated line/专线、power wall、hierarchical all-reduce（回收）、local SGD、periodic averaging、communication frequency、DiLoCo、inner/outer optimizer、OpenDiLoCo/INTELLECT（认名）、asynchronous training（回收深化）、staleness（回收）、decentralized training、gossip（认名）、gradient compression、Top-K sparsification、error feedback、PowerSGD（认名）、federated learning、FedAvg、non-IID。
- **定量环节**：跨域同步账（p=2 个 DC、10 Gb/s = 1.25 GB/s 专线、70B BF16 梯度 n=140 GB）：ring all-reduce 每端收发 2n(p−1)/p = n = 140 GB → **≈ 112 s/step**（不可行）；local SGD H=500：摊到每 step ≈ 0.22 s（且可与计算重叠）；DiLoCo 外环只传伪梯度再压缩 4×：≈ 0.06 s/step 等效——「同步频率是跨域训练的第一杠杆」算清全谱系（各档假设写明）。
- **图示**：① 多 DC 训练架构图（域内 3D 并行 + 域间外环，本课主图）；② 通信稀释谱系轴（频率 vs 风险）；③ 跨域 vs 集群内链路参数对照表。
- **延伸阅读**：《DiLoCo: Distributed Low-Communication Training of Language Models》（DeepMind 2023）；Prime Intellect 的 INTELLECT 技术报告（洲际训练实录，选读）；近年 multi-DC training 相关公开材料/综述（标注「以可查证来源为准」）。
- **误区**：「跨域训练 = 把 NCCL 跑在广域网上」——朴素同步差 2–3 个量级，必须换算法；「local SGD 掉点所以没用」——收敛税可测可控，工程上是「税率优化」问题；「联邦学习论文与我无关」——机制（压缩/异步/激励）是跨域训练的直接弹药库。

## L64 边缘与端云协同

- **文件**：`M9 前沿专题/L64 边缘与端云协同.md`
- **定位**：把推理搬向用户：端侧 LLM 的资源现实、端-边-云三级架构、协同推理机制谱系（split/投机/级联/路由）。课题组「边云协同」关键词的正课。
- **前置**：[[L55 推理性能模型]]、[[L58 量化推理]]、[[L59 投机解码]]、[[L60 分布式推理与PD分离]]
- **核心问题**：① 手机/车机到底能跑多大的模型（内存与带宽账）？② 端云之间可以怎么分工（有哪几种协同模式）？③ 什么时候该走端、什么时候该走云——这是个什么优化问题？
- **内容要点**：
  1. 动机四角：时延（RTT 物理下限 + 弱网）、隐私（数据不出端）、成本（云推理的钱账回收 L61）、离线可用；反方向的约束：端侧算力/内存/功耗/散热。
  2. **端侧资源现实**（定量开场，规格用 03 扩展速查区口径）：旗舰手机 ~12–16 GB 统一内存、LPDDR 带宽 ~50–100 GB/s、NPU 数十 TOPS（INT8）→ 用 L55 公式算端侧 decode 上限：3B-W4 模型 ≈ 1.5 GB 权重 → ~30–60 tok/s 量级——「端侧 = 小模型 + 极致量化」的物理必然；端侧栈认名：llama.cpp/MLC/ExecuTorch、NPU 生态碎片化一句话。
  3. **协同模式谱系**（本课主线，每种：机制图 + 通信量/时延分析 + 适用域 + 代表工作认名）：
     - **model cascade/路由**：小模型先答，难题升云（难度判断/置信度路由——「路由器即研究点」）；
     - **speculative edge-cloud**：端小模型打草稿、云大模型验证（回收 L59 机制的广域版——传 token 不传 KV，通信极小，时延结构分析）；
     - **split inference**：模型切两半端云各跑（传中间激活：算一笔激活尺寸账 vs token 账，说明为什么 LLM 时代 split 不如 CNN 时代香——激活太大）；
     - **KV/上下文迁移**：会话跨端云迁移（回收 L56 分层与 L60 传输）；
     - RAG 的端云分工一句话（检索在端/生成在云等组合，接 L70）。
  4. **决策问题形式化**（课题组视角收口）：min 成本/时延 s.t. 质量与隐私约束——在线决策（每请求路由）× 离线决策（模型放置/更新）；与 MEC/计算卸载文献的血缘辨析（网络背景读者的旧知识新用：offloading 理论可迁移，但 LLM 的自回归/KV 状态让问题结构全新）。
  5. 现实案例认名：Apple Intelligence 的端云双层（on-device + Private Cloud Compute）、手机厂商端侧模型（认名即可，标注「快速演化区」）。
  6. 与研究的连接（写实）：弱网/移动性下的会话连续性、端云投机的自适应 k、多用户边缘节点的资源分配、协同推理的 SLO 定义与评估基准缺失——open problems 清单。
- **必收术语**：edge inference、on-device LLM、NPU、unified memory、edge-cloud collaboration、computation offloading、model cascade、routing（模型选择语义）、speculative edge-cloud inference、split inference/model partitioning、intermediate activation transfer、KV migration、session continuity、MEC（认名）、Private Cloud Compute（认名）、llama.cpp/MLC（认名）、quality-latency-cost tradeoff。
- **定量环节**：三模式对比账（同一任务：输入 1K token、输出 300 token、RTT 50 ms、上行 20 Mb/s）：纯云（全部 token 网传+云 TTFT）vs 纯端（3B-W4 @40 tok/s → 7.5 s）vs 端云投机（端生成+云每轮验证的往返次数 × RTT + 少量数据）——算出各自 E2E 时延与流量，画出「哪种负载哪种网况谁赢」的相图雏形。
- **图示**：① 端-边-云三级架构图（本课主图）；② 协同模式谱系四联小图（cascade/speculative/split/migration）；③ 时延构成对比条形图（三模式）。
- **延伸阅读**：Apple《Private Cloud Compute》技术博客（架构现实样本）；近年 edge-cloud LLM serving 综述（arXiv，选一篇较新的，以实际检索为准）；MLC-LLM 文档（端侧部署的工程感）。
- **误区**：「端侧模型没用」——路由/草稿/隐私场景价值巨大，关键是协同设计；「split inference 是 LLM 的未来」——激活传输账常常不划算，要先算再信（本课算了）；「边缘 = 小一号的云」——资源结构、网络位置、故障模式、租户模型全不同。

## L65 推理服务生存性

- **文件**：`M9 前沿专题/L65 推理服务生存性.md`
- **定位**：课题组生存性主线的**推理侧**正课（与 L53 训练侧成对）：serving 的故障模型、failover 机制、降级服务、SLO 违约核算与多地域容灾。这些主题散见于工业论文但少有系统教材，本课把它们组织成一张地图。
- **前置**：[[L55 推理性能模型]]、[[L57 连续批处理与调度]]、[[L60 分布式推理与PD分离]]、[[L61 推理服务框架与集群]]；推荐先读 [[L53 大规模训练可靠性]]
- **核心问题**：① serving 的故障模型与训练有何本质不同（故障单位从 job 变成 request/session）？② 实例/节点/地域挂掉时，在飞请求和 KV/会话状态怎么办？③ 「生存性」怎么度量：可用性、SLO 违约率、恢复时间各自捕捉什么？
- **内容要点**：
  1. **故障模型对照表**（开场，本课骨架）：训练 = 离线作业、故障即全局停、指标是 goodput（回收 L53）；serving = 在线有状态服务、故障是局部的但 SLO 时刻在计时、指标是可用性/违约率——「分钟级恢复在训练里是优秀、在 serving 里是事故」。fail-stop / fail-slow 回收：慢实例在 serving 里表现为尾延迟污染（tail at scale 语境）。
  2. **状态分层与丢失语义**：无状态 API/router 层（易恢复）→ 引擎实例的在飞请求（重试或丢弃）→ **KV cache/会话状态**（丢失 = 重算的 TTFT 惩罚 或 迁移的传输成本——判据算例见定量②）→ 模型权重（无损但重载 = 冷启动，回收 L61）；PD 分离让故障面细化：P 挂 / D 挂 / KV 池挂各自的后果与恢复路径（回收 L60 Mooncake 架构）。
  3. **failover 机制谱系**：健康检查与摘除（探测间隔 vs 误判的两难）、请求重试（幂等性、超时预算、**retry storm** 的雪崩风险）、**hedged requests**（对尾延迟的经典武器，《The Tail at Scale》思想）、会话迁移 vs 就地重算、副本与 active-active/active-standby。
  4. **降级服务**（degraded service，课题组关键词，重点节）：过载或故障下的「有序退让」菜单——切小模型（cascade 回收 L64）、缩上下文/砍功能、关投机/换量化档、admission control 拒绝新请求保存量（回收 L57）；每项标注「质量-时延-成本」代价；**brownout** 思想；「降级是设计出来的能力，不是塌下来的状态」——SLO 分级（interactive/batch）在故障时的优先级语义。
  5. **多地域生存性**：region outage 的现实（云史大故障认名级）；多活部署与**容量 headroom**（N+1/N+2：冗余度 = 生存性 × 成本的核心权衡，与 L66 弹性/利用率互为表里）；地域间路由切换（DNS/anycast 一句话 + 回收 L61 路由）；模型/配置的多地域同步；会话连续性跨域（KV 跨域迁移的带宽/RTT 账，回收 L63 的 WAN 参数）。
  6. **度量体系**（收口到课题组评估语言）：**availability**（几个 9 → 年停机时间换算表）、**SLO violation rate**、恢复时间（检测→摘除→重路由→补容的分解，类比 L53 的故障时间线）、任务完成率；**error budget**（SRE 语言：可用性目标反过来定义「允许坏多久」）；评估方法：故障注入/混沌工程（接 L67 仿真+故障注入——课题组的评估路径）。
  7. 与研究的连接（写实）：故障感知路由与调度、KV 容灾放置（副本 vs 重算的最优策略）、降级策略的在线决策、多地域容量规划与成本、生存性基准与评估方法缺失——open problems 直接对接课题组主线三的推理半区。
- **必收术语**：availability、nines（99.9% 等）、downtime、SLO violation rate、error budget、failover、health check、probe、request retry、idempotency、retry storm、hedged request、graceful degradation/degraded service、brownout（提名）、load shedding、session migration、KV cache fault tolerance、active-active/active-standby、capacity headroom、N+1 redundancy、region outage、multi-region deployment、anycast（一句话）、chaos engineering/fault injection（认名）、RTO/RPO（认名）、blast radius（回收）。
- **定量环节**：三连算：① 可用性换算与组合：99.9% = 8.76 h/年停机；两地域各 99.5%、双活且各自留 50% headroom → 全站不可用 ≈ 0.5%² = 0.0025%（附「独立性假设」的批判性备注：相关故障让真实数字更差）；② 迁移 vs 重算判据（回收 L60 数字）：1.3 GB KV 走 400G RDMA ≈ 26 ms < 重算 4K prefill ≈ 145 ms → 域内迁移赢；跨域 RTT 100 ms + 1 Gb/s 时迁移 ≈ 10.4 s+ → 反转，算出翻转点；③ 降级收益：到达率超容量 20% 时不降级（ρ>1 队列发散、全员违约）vs 把 30% 流量切到 1/5 成本的小模型（ρ 回到 0.9）→ 用 L55 的排队公式对比 SLO 违约率——「降级不是认输，是把违约集中到可控处」。
- **图示**：① serving 故障面全景图（API/router/P 池/D 池/KV 池/region 各层故障点与对策标注——本课主图，与 L60 架构图同底）；② 降级决策菜单表（手段 × 质量/时延/成本代价）；③ 多地域双活与容量 headroom 示意。
- **延伸阅读**：《The Tail at Scale》（CACM 2013——尾延迟与 hedging 正典，本课必读）；Google SRE Book 的 SLO/error budget 章（在线服务方法论，免费在线）；Mooncake 论文的容错与超售部分回读（把 L60 读过的系统换生存性眼镜再读一遍）。
- **误区**：「加副本 = 高可用」——不设计容量 headroom、状态迁移与切换路径，副本只是摆设；「降级丢人」——error budget 语言下它是 SLO 工程的正当武器；「训练容错经验可以直接搬过来」——job 语义 vs request 语义、分钟级 vs 毫秒级预算，方法论要重建；「重试总是安全的」——非幂等操作 + retry storm 会把局部故障放大成全局雪崩。

## L66 弹性算力与资源效率

- **文件**：`M9 前沿专题/L66 弹性算力与资源效率.md`
- **定位**：课题组「资源效率」关键词的正课：用不稳定/碎片化的算力做正经事——spot 训练、弹性伸缩、GPU 共享与超卖、能耗与成本的度量。把 L35 调度、L53 可靠性、L61 扩缩的线头拧成「效率工程」总纲。
- **前置**：[[L35 GPU集群调度]]、[[L53 大规模训练可靠性]]、[[L61 推理服务框架与集群]]
- **核心问题**：① spot/抢占式算力便宜 60–90%，为什么大多数人用不起来？② 弹性训练/弹性推理各自的技术难点是什么？③ 「集群效率」到底怎么度量（利用率的层层折扣）？
- **内容要点**：
  1. 算力市场光谱：按需/预留/**spot（可抢占）** 的价格与可用性结构；「便宜的代价 = 随时被收回 + 供给波动」——把不确定性变成可管理风险是系统研究的活。
  2. **弹性训练**（spot 上训练的技术栈，回收 L53 并深化）：抢占信号（限时预警）→ 快速 checkpoint（回收谱系）→ **弹性重配**（DP 度变化的 batch/LR 语义、mesh 重建成本）→ 数据进度对齐；两大学术流派认名：**Bamboo**（PP 冗余计算硬扛抢占）、**Oobleck**（预生成流水线模板快速切换）、Varuna 等；「抢占率×恢复成本」的可行性判据。
  3. **弹性推理**：负载昼夜潮汐（画像）→ autoscaling 回收（L61）+ spot 承载无状态 replica 的模式；冷启动税复算；**错峰填谷**：训练/离线批推理吃夜间低谷（回收 L57 SLO tier）——「一个集群的 24 小时」示意图。
  4. **GPU 共享与切分**（提高单卡利用率）：**MIG**（硬件切分，隔离好粒度死）vs **MPS**（软件共享，粒度活干扰真）vs time-slicing；推理小模型合租、训练开发机复用的典型场景；干扰与 SLO 的测量方法一句话。
  5. **效率度量总纲**（本课交付物，收拢全课程的效率线）：层层折扣瀑布：装机算力 → 分配率（L35）→ goodput（L52/L53）→ MFU（L22）→ 每 token 成本（L61）→ **每焦耳 token**（能效：tokens/J 作为终极指标的趋势；碳感知调度认名）；「效率研究 = 在某一层折扣上抢回百分点」。
  6. 与研究的连接（写实）：多租户下训练+推理混部（推理波谷借卡给训练的调度机制）、spot 供给预测与组合（多可用区/多云套利）、生存性×效率的联合优化（冗余度怎么定——与 [[L65 推理服务生存性]] 的容量 headroom 议题互为表里，直接对接课题组「冗余部署-弹性调度-资源利用率权衡」）。

- **文件**：`M9 前沿专题/L67 测量仿真与评测.md`
- **定位**：研究方法课：没有万卡怎么做万卡研究——测量论文怎么读、公开 trace 怎么用、ASTRA-sim/ns-3/SimAI 怎么选、仿真可信度怎么立。课题组仿真主线（第 4 条）的正课，配套动手课 [[L68 实践-仿真上手]]。

  5. **可信度方法论**（审稿人视角清单）：校准（对齐 nccl-tests/真机小规模）、验证（重现已知结果）、敏感性分析（关键参数扫描）、报告仿真设置的完整性（拓扑/负载/故障模型全交代）；「仿真的价值不是替代真机，是做真机做不了的受控实验（万卡故障注入、未来硬件）」。

- **内容要点**：
  1. **VLM**：**ViT**（图像切 patch = 视觉的 tokenize）→ vision encoder + projector 接入 LLM；图像 = 数百~千 token 的「贵前缀」→ prefill 加重、多模态输入的调度不均（图文混批）；视频 = token 洪水（帧×patch）一句话；CLIP 认名。
  2. **扩散模型**：迭代去噪的直觉（噪声→图像，数十步 U-Net/DiT 前向）；**DiT**（Transformer 化的扩散骨干）；系统画像对照表：无 KV cache、每步全量计算、天然 compute-bound、时延 = 步数×单步——与 LLM decode 恰成镜像；serving 优化线索认名（步数蒸馏、cache 复用如 approximate caching、并行去噪）；视频生成 = 扩散×时间维的算力巨兽一句话。
  3. **Agentic workload**（对 serving 假设的冲击最大，重点）：请求不再独立——**多轮工具调用循环**（LLM→tool→LLM→…）：会话长、间歇空闲（工具执行期 KV 挂着占显存）、前缀高度可复用（system+历史）、尾部长度极不可控；对系统的新要求：KV 生命周期管理（挂起/迁移/换出，回收 L56 分层）、会话亲和路由（回收 L61）、agentic RL 的 rollout 系统（回收 L54）——「agent 把 serving 从『请求处理』变成『会话托管』」。
  4. **RAG 管线**：embedding model（回收 L10 伏笔）→ **vector database**（ANN 检索：HNSW 认名、召回-时延 trade 一句话）→ rerank → 长上下文生成；系统含义：检索层的时延预算、知识更新 vs 重训练的成本对比、「RAG vs 长上下文」的成本之争一句话。
  5. 收口：负载演化的通用启示——「模型结构与应用模式每变一次，系统研究就多一批题」（用 L55 的负载画像方法论把任何新负载画一遍，是课题组的可复用技能）。
- **必收术语**：multimodal、VLM、ViT、patch、vision encoder、projector、CLIP（认名）、image token、diffusion model、denoising step、U-Net（认名）、DiT、step distillation（认名）、video generation、agent/agentic workload、tool call/function calling（回收）、session、KV lifecycle、RAG、embedding model（回收）、vector database、ANN/HNSW（认名）、rerank、retrieval latency budget。
- **定量环节**：两笔对照账：① VLM：一张 1024×1024 图 ≈ 576–1024 视觉 token（按主流 patch 方案）→ 等效多长的文本前缀、prefill 时间增量（L55 公式）；② Agent 会话：平均 15 轮×每轮工具执行 3 s 空闲 → 一个会话挂起期占用的 KV 显存×时间积分 vs 换出-换入的传输成本（L56 口径）——「挂着还是搬走」的决策账。
- **图示**：① VLM 管线图（图像→patch→encoder→LLM）；② LLM vs 扩散的系统画像对照表；③ agent 会话时序图（LLM 段与工具段交替，标 KV 占用）。
- **延伸阅读**：任一主流开源 VLM 的模型卡（结构感）；主流视频生成系统的公开技术博客（算力体感，认知级）；vLLM/SGLang 对 multimodal 与 tool-call 的文档（工程现状）。
- **误区**：「多模态 = 换个输入格式」——token 经济与调度假设全变；「扩散和 LLM 的 serving 可以共用一套」——一个 memory-bound 自回归、一个 compute-bound 迭代，架构假设相反；「RAG 是模型技术」——四分之三是检索系统与数据工程。
